# frontend: the web app users work in

Installs the **React frontend** (its own repository,
`design-daas-application-frontend`) as `frontend.service`, and the nginx
site that serves it on **:8443** together with the auth service under
`/auth/`.

```
browser ─https :8443─ nginx (frontend.conf)
                        ├─ /        → daas-frontend container 127.0.0.1:5001 (nginx with the React build)
                        └─ /auth/   → auth service 127.0.0.1:AUTH_PORT (login, users, permissions)
browser ─https :443── nginx (daas.conf) → DaaS backend (VMs, containers, viewer)
```

## What you need

- The frontend repository next to this one
  (`/root/design-daas-application-frontend`, or `FRONTEND_FOLDER` in
  `installer/daas.env`).
- **The URL patch applied to it** (once per clone): the frontend must take
  the backend URLs as build arguments. Without it the installer stops.

  ```bash
  git -C /root/design-daas-application-frontend apply /root/design-daas/installer/frontend/frontend-env-urls.patch
  ```

- `make daas-configure` done before (it writes nginx.conf with the
  `upstream_front` upstream and the certificate this site uses).

## Which settings it uses (`installer/daas.env`)

| Setting | Used for |
|---|---|
| `FRONTEND_PUBLIC_URL` | nginx server name, `/etc/hosts` entry if the name does not resolve, certificate name (`daas-configure`) |
| `DAAS_PUBLIC_URL` | baked into the build: where the app calls the DaaS backend |
| `AUTH_PUBLIC_URL` | baked into the build: where the app logs in (normally `FRONTEND_PUBLIC_URL/auth`) |
| `OAUTH_CLIENT_ID` | baked into the build |
| `AUTH_PORT` | where `/auth/` is proxied to |

Defaults: `FRONTEND_PUBLIC_URL=https://HOST_NAME.HOST_DOMAIN:8443`. nginx
always listens on 8443; a different port in the URL only makes sense
behind another proxy.

The URLs are **compiled into the JavaScript**, so after changing them run
`make frontend-install` (rebuild), not only `make configure`.

## Commands

From `installer/`, as root:

| Command | What it does |
|---|---|
| `make frontend-all` | `frontend-configure` + `frontend-install` (step 6 of `make install`) |
| `make frontend-configure` | Writes the nginx site from `frontend.conf`, adds the name to `/etc/hosts` if needed, reloads nginx |
| `make frontend-install` | Writes `frontend/.env` from `daas.env`, builds the image from the current frontend code, installs and (re)starts `frontend.service` |
| `make frontend-check` | Tests the running frontend like a browser: service, container, page with a **valid certificate** for the name, deep link `/login`, `/auth/` reaching the auth service, and the three URLs inside the build. Changes nothing |
| `make frontend-status` / `frontend-logs` / `frontend-restart` | Service control |
| `make frontend-reinstall` | Delete + install, after frontend code changes |
| `make frontend-delete [PURGE=1]` | Removes service, container and image (`PURGE=1`: also the nginx site) |

## Files

| File | Content |
|---|---|
| `install.bash` | Builds the image (`docker-compose build`) and installs `frontend.service` |
| `configure.bash` | nginx site + name resolution |
| `delete.bash` | Removes what `install.bash` set up |
| `check.bash` | The test behind `make frontend-check` |
| `docker-compose.yml` | Build (target `server` of the frontend's Dockerfile, URL build args) and the container on `127.0.0.1:5001` |
| `frontend.conf` | nginx site template (`front1.cluster.local` and the auth service port are replaced) |
| `frontend-env-urls.patch` | The patch for the frontend repository (Dockerfile build args + `src/constants/constants.js`) |
| `.env` | Generated by `install.bash` from `daas.env` (mode 600, not committed) |

## Things to know

- The certificate is the one from `daas-configure`, signed by the local CA
  `/etc/nginx/ssl/daas-ca.crt`. Import that CA into the browser once.
- The name used to be guessed from the host name's last digit
  (`pve1` → `front1.cluster.local`); now it comes from
  `FRONTEND_PUBLIC_URL`, so a custom name also ends up in the certificate.
- The frontend repository may still contain `docker-compose-pve.yml` from
  the old install method; it is not used any more.
